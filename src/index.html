НАСТРОЙКА

Подключение

Подключите роутер и настройте экспорт сетевых потоков.

01

Проверка REST API MikroTik

Необязательно · не влияет на приём Traffic Flow

HTTPS использует службу www-ssl (обычно порт 443). Доверие самоподписанному сертификату небезопасно. Пароль не сохраняется.

Необязательно: запросы только читают текущую конфигурацию и аренды RouterOS по введённым данным. Привязка имени и MAC приблизительная; для истории фиксируется только недавно полученная аренда. Пароль не сохраняется.

02

Приём потоков

UDP-сборщик NetFlow v5, v9 и IPFIX

Принимаются только пакеты с указанного IPv4 роутера и адресов в списке ниже.

Обзор и сигналы объединяют данные по IP. Если сети роутеров пересекаются, хосты и потоки могут смешиваться; фильтр по экспортёру доступен в поиске. UDP-адрес источника не является криптографической аутентификацией.

03

Локальные подсети

Для определения входящего и исходящего трафика

Укажите все подсети за MikroTik, по одной на строку. Потоки без подсети соответствующей версии IP останутся неопределёнными. NAT и экспорт на нескольких интерфейсах могут влиять на направление и объём.

04   Правила безопасности и история

Пороги задаются для записей, полученных за 5 минут; это не точная скорость. Сигналы работают только после настройки локальных подсетей. Значения — стартовые, подберите под сеть.

Вручную заданные CIDR не подтверждают угрозу. Публичные базы репутации настраиваются отдельно ниже; домены не анализируются.

Сохраняются сигналы и пятиминутные агрегаты исходящего трафика по IP за выбранный срок, суточные общие агрегаты за 30 дней. Сырые потоки не сохраняются. История может содержать IP и сведения об активности; ограничена 10 000 событий и 100 000 агрегатов. Очистка необратима.

06

Уведомления Windows

Локальные оповещения выключены по умолчанию

Новые сигналы объединяются; повтор того же типа и IP не чаще 30 минут. После пяти минут без пакетов показывается отдельное предупреждение. Уведомления работают только при запущенной программе и не отправляются через интернет.

05

Базы репутации IP

Проверка по локальному кэшу публичных списков

Загружаются IPsum (не менее трёх списков) и Blocklist.de через FireHOL. Запросы идут к GitHub; ваши внутренние IP и потоки не отправляются. Источники могут пересекаться. Данные старше 72 часов или без даты источника не используются.

Совпадение — сигнал для проверки, не доказательство угрозы и не основание для автоматической блокировки. IPv6, домены и определение типа вредоноса этими списками не покрываются.

NET CONTROL / СПРАВКА

      

        
01 Что делает программа
Net Control принимает метаданные потоков Traffic Flow от MikroTik по UDP и локально показывает трафик, направления, сигналы и отчёты. Поддерживаются NetFlow v5, v9 и IPFIX. Программа не получает содержимое пакетов и не является антивирусом.
Сырые потоки хранятся только в памяти: последние 5 минут, не более 50 000 записей. При включении истории локально сохраняются сигналы и агрегаты. Остановка сбора сохраняет текущее окно до его истечения; перезапуск сбора, очистка или закрытие приложения удаляют данные. Время записи — время получения экспорта, а не начало соединения.

        
02 Первоначальное подключение
  1. Установите и запустите Net Control на компьютере, доступном MikroTik по сети.
  2. Откройте Подключение, укажите IPv4 роутера и UDP-порт сборщика (по умолчанию 2055). Приложение принимает пакеты только с указанного IP источника.
  3. Проверьте определённый IPv4 компьютера в блоке Traffic Flow. Адрес определяется по маршруту ОС, но не гарантирует обратную доступность; при необходимости выберите или введите правильный адрес. Не используйте localhost / 127.0.0.1.
  4. На роутере выполните показанные в приложении команды. Если target уже существует, измените его вместо создания дубликата. interfaces=all может дублировать учёт на разных интерфейсах — выбирайте интерфейсы в соответствии с вашей схемой сети.
  5. Разрешите входящий UDP-порт сборщика в брандмауэре Windows, ограничив источник адресом роутера, и нажмите Запустить сбор. Экспорт записей может задерживаться до истечения тайм-аута RouterOS.
Сбор запускается вручную при каждом открытии приложения и работает независимо от проверки REST API.

        
03 Необязательная проверка RouterOS REST API
Проверка доступна для RouterOS 7 и читает только /rest/system/resource; она не включает Traffic Flow и не меняет конфигурацию. Используйте пользователя с минимально необходимыми правами чтения.
Кнопка «Получить текущие DHCP-аренды» по запросу читает активные аренды RouterOS через REST API, без сохранения пароля. Снимок доступен 5 минут и не гарантирует привязку IP к устройству в момент старого события. При включённой истории доступный снимок сохраняется с событием.
Для HTTPS нужна служба www-ssl с назначенным сертификатом; обычно это порт 443. Флажок доверия самоподписанному сертификату отключает проверку и небезопасен — он не создаёт сертификат на роутере. Для HTTP используется служба www, обычно порт 80, но он может быть изменён (например, 800). Состояние и реальные порты: /ip service print.
HTTP передаёт пароль открытым текстом. Используйте HTTPS с доверенным сертификатом; HTTP допустим только в доверенной сети или защищённом туннеле. Пароль на диск не сохраняется.

        
04 Подсети и направления
В разделе Локальные подсети введите все IPv4- и IPv6-сети за роутером в формате CIDR, по одной на строку, и сохраните, например 192.168.88.0/24. Настройки сохраняются локально и применяются к текущему окну.
  • Исходящий: из указанной сети наружу. Входящий: извне в указанную сеть.
  • Внутренний: между указанными сетями. Транзитный: оба адреса вне указанных сетей.
  • Не определён: не задана подсеть соответствующей версии IP или в записи смешаны версии адресов. Это направление по адресам в потоке, а не по физическому интерфейсу.
Неполный список сетей, NAT, sampling и экспорт на нескольких интерфейсах могут исказить направления и объёмы. В карточке хоста входящий и исходящий считаются относительно его IP, независимо от списка сетей.

        
05 Обзор, типы трафика и хосты
На обзоре показаны объём, число потоков, источники, сигналы и распределение за пять минут. Диаграмма основана на времени получения записей. В таблице источников нажмите заголовок столбца для сортировки; сортировка применяется ко всем источникам, затем показываются первые 30.
Типы «Почта», «IP-телефония», «Медиа», «P2P», «Веб» и другие предполагаются только по порту и протоколу, в том числе по порту источника обратного потока. Это не доказательство использования приложения и не определение владельца IP. HTTPS/QUIC не разделяется надёжно на конкретные сайты и сервисы.
Нажмите IP в таблице или сигнале: карточка показывает объёмы в обе стороны, предполагаемые типы, контрагентов в отчёте и до 200 последних записей. Хост может быть и источником, и назначением; суммы разных карточек нельзя складывать.

        
06 Сигналы безопасности
Настройте локальные подсети: без них анализ сигналов отключён. Правила, пороги, исключения, доверенные почтовые серверы и вручную заданные адреса пулов задаются в разделе «Подключение → Правила безопасности и история». Выявляются возможное сканирование, SMTP-рассылка, майнинг, исходящая высокая нагрузка и входящая атака. По умолчанию для нагрузки используется 100 000 экспортированных пакетов и 20 МБ для исходящей, либо 30 внешних источников и 100 000 пакетов для входящей. Это стартовые пороги, их необходимо подобрать под сеть.
Окно считается по времени получения записей, а не по точному моменту пакетов. Известные порты/адреса и длительность потока — лишь признаки; длительность доступна только если экспортёр прислал корректное время. Для IPv6 необходимо отдельно указать локальные IPv6-подсети; базы репутации пока содержат только IPv4. NAT, sampling и дублирование интерфейсов влияют на результаты.
Это не подтверждение вируса или атаки. Возможны ложные срабатывания и пропуски; обычные службы могут использовать те же порты. Сопоставляйте сигналы с DNS, firewall, журналами и проверкой конечного устройства перед блокировкой.

        
07 Отчёт и конфиденциальность
Кнопка Сохранить отчёт открывает диалог сохранения HTML на компьютере. В отчёте: сводка текущего окна, направления, предполагаемые типы, до 100 сигналов, рекомендации, до 30 источников и разбор до 20 наиболее активных. Для каждого показаны до 10 контрагентов и 20 последних записей.
При включённой истории сигналы и агрегаты по IP хранятся до выбранного срока (1–30 дней), общие суточные данные — до 30 дней с ограничением по размеру. После 20 наблюдаемых пятиминутных окон за 3 дня используется приблизительное среднее для контекста исходящей нагрузки; пустые окна в среднее не входят. На границах окон, при пропусках экспорта и смене IP сравнение может вводить в заблуждение. История по умолчанию выключена; выключение не удаляет уже сохранённые данные, их можно очистить отдельно.
Отчёт содержит IP-адреса и сетевую активность — храните его как конфиденциальный. Сырые потоки и отчёты никуда не отправляются. Если история включена, события и агрегаты сохраняются локально. Для проверки обновлений приложение обращается к GitHub, а установка нового выпуска требует подтверждения. Список подсетей сохраняется локально.

        
08 Устранение неполадок и обновления
  • Нет UDP-пакетов: проверьте адрес источника экспорта на MikroTik, маршрут до компьютера, target и брандмауэр Windows. Автоматически выбранный IP компьютера нужно подтвердить.
  • Пакеты есть, потоков нет: проверьте версию экспорта и дождитесь повторной отправки шаблонов v9/IPFIX. Неизвестные шаблоны и поля не интерпретируются.
  • ECONNREFUSED: проверьте IP, порт службы www/www-ssl, ограничения доступа и firewall. Ошибка TLS: проверьте сертификат и протокол/порт.
  • Неверные объёмы: проверьте sampling, NAT, потери UDP, дублирование интерфейсов и лимит 50 000 записей; внизу обзора показаны отброшенные из-за лимита записи.
  • Обновление недоступно: нужен интернет и опубликованный стабильный GitHub Release с совместимым setup.exe и latest.yml. Артефакты Actions сами по себе не являются обновлениями. В режиме разработки обновление отключено.
Перед установкой обновления сохраните нужный отчёт: программа перезапустится и потоки в памяти будут потеряны. Установщик не подписан; Windows SmartScreen может предупреждать. Проверяйте владельца репозитория и источник файлов.

        
09 Базы репутации и диаграммы
Приложение загружает публичные списки IPsum ≥3 и Blocklist.de через FireHOL с GitHub; внутренние IP и сами потоки не отправляются. Списки могут пересекаться, адрес может быть общим или ошибочно отмеченным. Совпадение не означает майнинг, спам или DDoS и не запускает блокировку.
Источники, даты и ошибки показаны в «Подключение → Базы репутации IP». Можно выключить проверку и загрузку, обновить базы вручную или очистить локальный кэш. Данные старше 72 часов либо без даты свежести не используются. Для IPsum дата изменения файла в GitHub лишь косвенно показывает свежесть исходных списков; для Blocklist.de учитывается и дата исходного файла. IPv6, DNS и домены этими списками не проверяются.
Четыре плитки на обзоре открывают текущие сигналы и связанные с их расчётом потоки. DDoS-плитка показывает все потоки соответствующего направления отмеченного хоста, не утверждая, что каждый из них вредоносный. Новые диаграммы показывают объём по времени получения записей, топ источников, направления и историю по дням при включённом хранении. Отсутствие данных не означает отсутствие трафика.

        
10 Поиск, расследование и диагностика
На обзоре показаны счётчики приёма, неизвестных шаблонов и ошибки структуры; потери до приложения ими не измеряются. Можно настроить несколько IPv4 экспортёров на одном порту. Обзор, сигналы и история суммируют данные по IP; при пересекающихся подсетях или дублированном экспорте результаты могут смешиваться. Поиск потоков поддерживает фильтр по экспортёру и выгрузку CSV или JSON.
В карточке хоста можно вести локальную заметку об IP и видеть связи и сохранённую историю исходящей нагрузки. В плитках сигналов кнопка «Разобрать» показывает пороги, причины и позволяет записать статус и заметку; они сохраняются по типу сигнала и IP, не подавляют сигналы и не доказывают угрозу. IP может перейти другому устройству.
Локальные уведомления Windows включаются в настройках. Повторы ограничены, предупреждение о пяти минутах без пакетов не доказывает неисправность. Срок хранения событий и агрегатов по IP можно выбрать от 1 до 30 дней; сокращение удаляет старые данные. Сырые потоки остаются только в памяти.
Кнопка «Проверить Traffic Flow» только читает настройки и targets RouterOS и не гарантирует доставку. Команды показаны для ручной проверки; приложение не изменяет настройки роутера.
