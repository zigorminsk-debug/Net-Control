# Net-Control — анализатор сетевого трафика и угроз

**Net-Control** — программное обеспечение для системных администраторов,
которое анализирует трафик сети и выявляет подозрительные действия
хостов, характерные для вирусной активности: **криптомайнеры,
спамеры, ботнеты (C2), сканерады, эксфильтрацию данных, син-флуд и
DDoS-атаки**.

Программа представляет собой **HTML-интерфейс (GUI)**, подключённый к
Python-ядру анализатора, и упаковывается в один исполняемый файл
**`setup.exe`**, который не требует установки Python.

## Что делает программа

Системный администратор получает инструмент, который:

1. **Принимает трафик** тремя способами:
   - загрузка **pcap-файла** (снимок трафика из Wireshark, tcpdump,
     инструментов SPAN/порт-микроскопии);
   - **демо-анализ** — синтетический сценарий для быстрого знакомства
     с интерфейсом и возможностями детекции;
   - **живой захват** с сетевого интерфейса прямо на сервере (Windows
     + Npcap).

2. **Анализирует пакеты** на уровне Ethernet/IP/TCP/UDP, расшифровывает
   **DNS-запросы**, извлечёт **SNI из TLS-handshake**, распознаёт
   **HTTP-запросы**, TCP-флагами и полезными нагрузками.

3. **Детектирует вредоносную активность** по сигнатурам и
   статистическому анализу потоков (подробнее в
   [категории угроз](#категории-угроз)).

4. **Присваивает каждому хосту риск-балл (0–100)** и уровень
   критичности, показывает доказательства (evidence) каждой тревоги.

5. **Отображает результаты** в веб-интерфейсе: дашборд, хосты,
   тревоги, статистика протоколов, топ-хосты, диаграммы.

## Возможности

| Решение | Как работает |
|---|---|
| 🔍 **Криптомайнинг** | Порты Stratum (3333/4444/5555/14444/…), известные пулы (minexmr, nicehash, nanopool…), SNI/DNS/HTTP-домены пулов, маркеры payload (`stratum`, `xpub`, login/submit-сообщения) |
| 🕸 **C2 / ботнеты** | Связь с известными C2-IP/доменами, **бипинг** — регулярные периодические подключения к одному адресу (CV-анализ интервалов) |
| 📨 **Спам / фишинг** | SMTP-рассылки с множеством адресатов, спам-ключи в payload, фишинговые HTTP-запросы |
| 🎯 **Сканирование и эксплойты** | Попытки доступа к `/wp-login.php`, `/.env`, `/xmlrpc.php`, `/.git/config`, SQL-инъекции (union select, or 1=1…) |
| 💤 **Эксфильтрация данных** | Резкий выброс исходящих данных на внешний адрес (объём + коэффициент исход/вход) |
| 💥 **Син-флуд** | Массовая отправка SYN-пакетов с одного хоста |
| 🌐 **DDoS** | Массовые SYN-запросы со многих источников на одну цель |
| 🧩 **DGA-подобные DNS** | Запросы к доменам с высокой энтропией на подозрительных TLD (.xyz, .top, .tk…) |
| 💰 **Крипто-адреса** | Биткоин-адреса в payload (кражи/отмывание) |
| 📊 **Риск-оценка** | Суммарный балл по категориям, цветовая индикаторная система, доказательства каждой тревоги |
| 💾 **Сохранение** | Последний результат анализа сохраняется в JSON и восстанавливается после перезапуска |

## Гайнд по интерфейсу

Интерфейс открывается в браузере автоматически при запуске
**Net-Control.exe** по адресу `http://127.0.0.1:8123`.

```
┌──────────────────────────────────────────────────────────────┐
│ Net-Control · анализатор сетевого трафика и угроз  [状态]   │
├──────────────────────────────────────────────────────────────┤
│ [📂 Открыть pcap] [🧪 Демо-анализ]   ↔ перекиньте .pcap      │
│ Интерфейс: [____] ▶ Начать захват   ■ Остановить              │
├──────────────────────────────────────────────────────────────┤
│ Хосты в анализе | Тревоги | Критичные | Трафик | Риск сети   │
├──────────────────────────────────────────────────────────────┤
│ 📈 трафик по времени      │ ⚠ тревоги по категориям          │
│                           │ 🍩 протоколы                      │
├──────────────────────────────────────────────────────────────┤
│ Хосты | Тревоги | Сеть | Настройки                            │
└──────────────────────────────────────────────────────────────┘
```

### 1. Панель управления (верхняя панель)

- **Открыть pcap-файл** — выбор файла снятия трафика. Файл можно
  также **перекинуть** на область «перекиньте файл .pcap сюда».
- **Демо-анализ** — запуск синтетического сценария с майнером,
  спамером, C2, сканером, эксфилом и DDoS. Идеально для первого
  запуска и проверки работы детекций.
- **Интерфейс + Начать захват / Остановить** — живой захват трафика
  прямо с сетевого адаптера (Windows + Npcap).
- **Статус-пил** в правом углу: `ожидание данных`, `📁 Файл
  проанализован`, `🧪 Демо-анализ`, `🟢 Живой захват · N пакетов`.

### 2. Карточки KPI

- **Хостов в анализе** — сколько IP-адресов参与 анализ (и режим).
- **Тревоги всего / Критические** — общее число тревог и число
  критических.
- **Объём трафика** — суммарный объём обработанных данных и
  длительность снимка.
- **Уровень риска сети** — максимальный риск-балл среди хостов.

### 3. Диаграммы

- **Трафик и тревоги по времени** — объём данных и число тревог по
  10-секундным бинам (линейный график).
- **Тревоги по категориям** — столбчатая диаграмма по типам угроз.
- **Распределение протоколов** — доля TCP/UDP/ICMP и др. (пончик).

### 4. Вкладка «Хосты»

Список всех хостов с колонками:

| Колонка | Значение |
|---|---|
| IP-адрес | адрес хоста |
| **Риск** | балл 0–100 (зелёный/жёлтый/красный) |
| Уровень | критический / предупреждение / информация |
| Пакеты, Исх. данные | статистика трафика хоста |
| Подкл., Портов | число подключений и различных портов |
| Категории | цветные бейджи найденных угроз (с числом сигналов) |

- Поиск по IP, фильтр по уровню, сортировка по колонкам.
- **Клик по строке** открывает детальную карту хоста:
  - круговой **рисков-гайд** (gauge);
  - статистика (пакеты, исход/вход, подключения, порты, DNS);
  - **тревоги хоста** с доказательствами;
  - **соединения** (топ по пакетам: адрес, порт, объём);
  - **DNS-запросы** хоста.

### 5. Вкладка «Тревоги»

Все обнаруженные события с фильтрами по категории и серьёзности,
поиск по хосту/описанию. Каждая тревога содержит **доказательства**
(evidence): порт, домен, интервал, объём — то, на чем основано
детектирование.

### 6. Вкладка «Сеть»

Распределение по протоколам и **топ-хосты по объёму трафика**.

### 7. Вкладка «Настройки»

Пороги детектирования (см. [настройки](#настройки-порогов)).
Изменения сохраняются и применяются к новым анализам.

## Установка

### Вариант А — готовый `setup.exe` (рекомендуется)

1. Скачайте **`Net-Control.exe`** из [Releases](../../releases)
   (или из артефактов Actions, см. ниже).
2. Запустите файл дважды. **Нет необходимости устанавливать Python** —
   всё включено в один файл.
3. Интерфейс откроется автоматически в браузере
   (`http://127.0.0.1:8123`). Если браузер не открылся, перейдите
   вручную по этому адресу.
4. Закройте окно, чтобы завершить работу.

### Вариант Б — запуск из исходников

```bash
git clone <ссылка на репозиторий>
cd Net-Control
python main.py
```

Требуется Python 3.9+ (без внешних зависимостей). Интерфейс
откроется автоматически.

## Требования

| Способ использования | Требования |
|---|---|
| `setup.exe` | Windows 10/11 x64 (PyInstaller собирает только для Windows) |
| Запуск из исходников | Python 3.9+ на любой ОС (Linux/macOS/Windows) |
| **Живой захват** | Windows + [**Npcap**](https://npcap.com) (галочка «Install Npcap in WinPcap API-compatible Mode») + права администратора |
| Анализ pcap-файла / демо | ничего дополнительно |

> **pcapng-формат** не поддерживается. Если у вас `.pcapng`, откройте
> файл в Wireshark и сохраните как pcap:
> *File → Export Packets → as pcap*.

## Как использовать

### 1. Демо-анализ (для первого запуска)

Нажмите **🧪 Демо-анализ**. Программа сгенерирует синтетический
снимок трафика (~900 пакетов) с заранее заложенными вредоносными
сценариями:

| Хост | Сценарий | Ожидаемые тревоги |
|---|---|---|
| `192.168.1.20` | криптомайнер | майнинг, DGA-DNS |
| `192.168.1.30` | спаммер/сканер | спам, сканирование |
| `192.168.1.40` | бот из ботнета | C2, бипинг |
| `192.168.1.50` | сканирующий хост | сканирование |
| `192.168.1.60` | эксфильтрация | эксфильтрация |
| `192.168.1.70` | жертва DDoS | DDoS |
| `192.168.1.10/11/12` | нормальный трафик | (не должен быть поднят) |

Это позволяет за 10 секунд убедиться, что программа и детекции
работают.

### 2. Анализ pcap-файла

Подготовьте снимок трафика:

- **Wireshark**: выберите захват на интерфейсе → *Stop* →
  *File → Save As* → формат **pcap**.
- **tcpdump**: `tcpdump -i eth0 -w capture.pcap`
- Для анализа всей сети используйте SPAN-порт или порт-микроскопию
  на коммутаторах.

Затем в Net-Control: **Открыть pcap-файл** (или перекиньте файл).
Программа обработает снимок и представит результаты.

> Рекомендация: для поиска вредоносности хватает захвата
> **внешнего трафика** (шлюз/фильтр) плюс DNS. Если нужны детали
> внутри网段, захватывайте смешанно, но помните о объёме файла.

### 3. Живой захват трафика

1. Установите **Npcap** (см. требования) и запустите Net-Control
   от имени администратора.
2. В строке «Интерфейс» нажмите **загрузить список** и выберите
   нужный сетевой адаптер (или введите его имя вручную —
   например, `\Device\NPF_{GUID}`).
3. Нажмите **▶ Началь захват**. Программа анализирует поступающие
   пакеты в реальном времени, обновляя дашборд каждые несколько
   секунд.
4. **■ Остановить** — завершить захват. Результат остаётся на экране
   и сохраняется.

> Для захвата трафика всего网段 нужен SPAN/микроскопия — программа
> читает трафик с одного интерфейса.

### Понимание результатов

- **Риск-балл** хоста (0–100) — сумма весов найденных категорий.
  Подключёны цвета: **≥60** — критический (красный), **≥25** —
  предупреждение (жёлтый), иначе — информация.
- **Уровень** хоста — критический/предупреждение/информация.
- **Тревоги** — каждое детекционное событие с категорией,
  серьёзностью и **доказательствами** (порт, домен, интервал, объём).
- **Категории** в списке хостов — число сигналов по каждому типу
  угроз.

## КатегориES угроз

| Категория | Как определяется | Вес (вклад в риск) |
|---|---|---|
| **Криптомайнинг** | порты Stratum; домены известных пулов (DNS, SNI, HTTP Host); маркеры payload | 45 |
| **C2-командный центр** | соединения с известными C2-IP/доменами | 45 |
| **DDoS** | >N различных источников SYN на одну цель | 35 |
| **Эксфильтрация** | исходящий объём >10 МБ с коэффициентом исход/вход ≥4 | 30 |
| **Сканирование** | >20 различных портов-целей (критично ≥60); exploit-пути; SQL-инъекции | 25 |
| **Бипинг** | ≥6 packets с регулярными интервалами (CV ≤0.5) к одному адресу (DNS исключён) | 20 |
| **Син-флуд** | ≥200 SYN-пакетов с одного хоста | 20 |
| **Спам** | SMTP с множеством адресатов; спам-ключи в payload | 18 |
| **Подозр. DNS** | домены с высокой энтропией на подозрительных TLD (DGA-подобные) | 15 |
| **Крипто-адреса** | биткоин-адреса в payload | 5 |

Детекции基于 **сигнатурный анализ** (порт/домен/payload) и
**статистику потоков** (бипинг, сканирование, флуд, эксфильт, DDoS),
поэтому работают без машинного обучения и без доступа к
шифрованному содержимому TLS (SNI используется вместо дешифровки).

## Настройки порогов

Вкладка **Настройки** позволяет настраивать пороги:

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `scan_ports_warn` / `scan_ports_crit` | число различных портов для сканирования (предупреждение/критично) | 20 / 60 |
| `beacon_min_count` | минимум пакетов в потоке для бипинг-анализа | 6 |
| `beacon_max_interval` | макс. средний интервал бипинг-соединений (сек) | 3600 |
| `exfil_mb` | минимальный объём исходящих данных для эксфильтрации (МБ) | 10 |
| `exfil_ratio` | коэффициент исход/вход для эксфильтрации | 4 |
| `dns_entropy` | порог энтропии домена для DGA-детекции | 4.0 |
| `syn_flood_count` | число SYN-пакетов для син-флуда | 200 |
| `ddos_src_count` | число источников SYN для DDoS на одну цель | 80 |

## Сборка setup.exe

`setup.exe` собирается из исходников с помощью **PyInstaller** и
GitHub Actions. Сборку нужно выполнять на **Windows** (PyInstaller
не создает Windows-исполняемые файлы на других ОС).

### Сборка через GitHub Actions (рекомендуется)

1. Отправьте изменения в репозиторий (push или PR).
2. Зайдите в раздел **Actions** → workflow **`build-setup-exe`**.
3. НаWait выполнения. Два job:
   - **smoke-test** — проверка ядра анализатора на Linux;
   - **build-setup** — сборка `Net-Control.exe` на `windows-latest`.
4. После успеха в разделе **Artifacts** скачайте артефакт
   **`Net-Control-setup-exe`** (файл `dist/Net-Control.exe`).

**Создание релиза:** поставьте метку (tag) вида `v1.0.0` на ветку с
изменениями. Как только workflow пройдет, автоматически создастся
**GitHub Release** со стеклянным `Net-Control.exe` (джоб `release`).

### Сборка локально на Windows

```bat
git clone <ссылка>
cd Net-Control
build_setup.bat
```

или вручную:

```bat
pip install pyinstaller
python build_setup.py
```

Результат: `dist\Net-Control.exe` (~15–25 МБ, один файл, без
консоли, открывает браузер автоматически).

```
Net-Control/

│   └── build-setup.yml          # GitHub Actions: smoke-тест + сборка exe
├── app/
│   ├── analyzer.py              # ядро: парсинг pcap + детектирование
│   ├── signatures.py            # сигнатуры угроз + настройки порогов
│   ├── demo_gen.py              # генератор демо-pcap (сценарии угроз)
│   ├── capture.py               # живой захват через Npcap (ctypes)
│   ├── storage.py               # сохранение результата в JSON
│   ├── server.py                # HTTP-сервер: static + REST-API
│   └── web/index.html           # HTML-интерфейс (GUI)
├── tests/

```

**Поток данных:** браузер → HTTP-API → `analyzer.py` (парсинг пакетов
→ агрегация по хостам/потокам → сигнатурные и статистические
детекции → риск-баллы) → JSON → интерфейс.

REST-API (для интеграции):

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/status` | состояние и счётчики |
| GET | `/api/stats` | сводка по текущему результату |
| GET | `/api/hosts` | список хостов |
| GET | `/api/hosts/<ip>` | детали хоста |
| GET | `/api/alerts` | тревоги (фильтры: category, severity, host) |
| POST | `/api/analyze` | загрузка pcap (raw body) |
| POST | `/api/demo` | демо-анализ |
| POST | `/api/capture/start` | живой захват {"interface": "..."} |
| POST | `/api/capture/stop` | остановка захвата |
| GET/POST | `/api/settings` | настройки порогов |
| GET | `/api/interfaces` | список интерфейсов Npcap |

## Как дополнить сигнатуры угроз

Списки вредоносных доменов/адресов/путей поддерживаются в
`app/signatures.py`. Чтобы не редактировать код, создайте файл
**`app/signatures.user.json`**:

```json
{
  "mining_domains": ["pool.my-pool.example"],
  "c2_ips": ["203.0.113.10"],
  "c2_domains": ["agent.evil.example"],
  "scan_paths": ["/admin.php"],
  "spam_keywords": ["lotto winner"]
}
```

Списки из этого файла **объединяются** со встроенными. Пороговые
настройки можно менять в интерфейсе (вкладка «Настройки»).

## FAQ

**Q: Почему не открывается интерфейс?**
Зайдите по адресу `http://127.0.0.1:8123` вручную. Если порт занят,
программа自动 выберет следующий (до +20). Проверьте, не блокирует
ли антивирус или corporate-брандмауэр локальный HTTP-сервер.

**Q: Живой захват не работает?**
Проверьте: 1) Windows (сборка exe); 2) Npcap установлен с галочкой
WinPcap-compatible mode; 3) запуск от администратора. Если интерфейс
не появился в списке — введите имя интерфейса вручную
(`pcap`-имя, как в Wireshark, например `\Device\NPF_{…}`).

**Q: Файл decode не работает / выдаёт ошибку формата?**
Поддерживается только pcap (не pcapng). Сохраните снимок в pcap
(Wireshark: File → Export Packets → as pcap).

**Q: Можно ли анализировать перекриптованный TLS-трафик?**
Детекции используют метаданные: порт, SNI, DNS, размеры/интервалы.
Содержимое TLS не расшифровывается — это достаточно для поиска
майнеров/ботов по поведению и сигнатурам.

**Q: Почему нормальный хост получил предупреждение?**
Проверьте доказательства (evidence) в тревогах — там указано, по
чему детектировано. Пороги можно повысить в «Настройки».
Демо-анализ показывает, как выглядят «чистые» хосты (уровень
информация).

**Q: Как изменить порт или разрешить доступ по сети?**
Запуск с параметрами: `Net-Control.exe --host 0.0.0.0 --port 8123`
(для исходников: `python main.py --host 0.0.0.0`). Учтите
безопасность: интерфейс без авторизации, разрешайте доступ только
вам.

## Разработка

- Проверка ядра: `python tests/test_smoke.py`
- Режим разработки: `python main.py --no-browser`
- Прогоны CI: push в репозиторий → workflow `build-setup-exe`
  (smoke-тест на Linux + сборка exe на Windows).

Согласованные изменения: добавить сигнатурную проверку в
`app/analyzer.py` (`process_packet`/`_finalize_host`), список в
`app/signatures.py`, а тест — в `tests/test_smoke.py`.

---

*Net-Control — инструмент системного администратора для анализа
сетевого трафика и поиска вредоносной активности. Работает без
интернет-подключения и без отправки данных на сторонние серверы.*
